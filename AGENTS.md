# AGENTS.md

Guidance for agents (and people) working in this repo. Read this before making
changes. The site's own plan is in `PLAN.md`; the internationalization plan and
translation workflow are in `docs/internationalization.md` and
`docs/translation-workflow.md`.

## What this repo is

A Hugo static site for oxrok, deployed to https://oxrok.dev via GitHub Pages.
The build is `make` (see `Makefile`), which regenerates data and docs from the
sibling `../oxrok` checkout, builds with Hugo, indexes with Pagefind, and runs
`tools/check.py`. CI runs this on every push and on a daily schedule.

## Core principle: "generated, not written"

Driver facts must never go stale or be hand-maintained. They come from the oxrok
repo at build time:

- `data/drivers.json` is generated by `make data` from `../oxrok/tools/site-data`
  and is **gitignored** — never edit it, never commit it.
- `data/ui.json` is generated by `make ui` (from `../ui`) and **is committed**.
- `content/devices/*.md` are generated stubs by `tools/gen-driver-pages.py` — the
  template renders everything from `data/drivers.json`, so the stub only carries
  `key`, `title`, and `type`. Regenerate with `make pages` (never hand-edit the
  facts into them).
- `data/decoders.json` is generated by `make decoders` (`tools/decoder-data.py`)
  from `oxrok -L`, `oxrok -P <id> --show` and the checklist in
  `../oxrok/docs/NATIVE_DECODERS.md`, and is **gitignored**. It fails the build
  if the binary and the checklist disagree on which decoders are native.
  The decoder examples (list in `EXAMPLES` there) are real runs on captures in
  `../oxrok/tests/fixtures`; a command that fails or prints nothing fails the
  build. Each example needs `dec_ex_<key>_h` and `dec_ex_<key>_p` in every
  i18n catalog.
- `content/decoders/*.md` are generated stubs by `tools/gen-decoder-pages.py`
  (`key`, `title`, `type: decoders`), written by `make pages` alongside the
  driver stubs.
- `content/docs/decoders.md` is copied from `../oxrok/docs/DECODERS.md` by
  `make docs` on every build.

- `assets/changelog/oxrok.md` is generated by `make docs`
  (`tools/import-docs.py`) from `../oxrok/CHANGELOG.md`, and is
  **gitignored**. See "Changelog" below.

If you find a stale or wrong fact, fix it in the oxrok repo (`docs/drivers.toml`
or `tools/site-data`), not in this repo.

## Internationalization (the part with all the gotchas)

The site is multilingual: English (default, at `/`), and per-language subtrees
`/zh/`, `/es/`, etc. A language is declared in `hugo.toml` **only once it has
content**, so an empty language site is never built.

When adding or editing translated content, remember these — each one bit us:

### Hugo multilingual setup

- Each language needs an **explicit `contentDir`** in `hugo.toml`:

  ```toml
  defaultContentLanguage = "en"
  defaultContentLanguageInSubdir = false   # English stays at /

  [languages.en]
  languageCode = "en"
  languageName = "English"
  contentDir = "content"
  weight = 1

  [languages.zh]
  languageCode = "zh-Hans"
  languageName = "简体中文"
  contentDir = "content/zh"
  weight = 2
  ```

  Without the explicit `contentDir`, Hugo (0.169) renders sub-pages in the wrong
  language. (`languageCode`/`languageName` are deprecated in favor of
  `locale`/`label` since 0.158, but still work — a clean-up task, not urgent.)

- **Sectioned content needs an explicit `type` in front matter**, or it falls
  back to `_default` templates. `content/zh/devices/` is not type `devices`; it's
  type `zh` unless you say so:

  ```md
  ---
  title: 设备
  type: devices
  ---
  ```

  The generator writes `type: devices` into every driver stub. Docs pages use
  `type: docs`; the blog uses `type: blog`.

- **Page links use `relLangURL`, not `relURL`.** `relURL` is not language-aware
  and produces `/devices/` even on `/zh/` pages. Static assets
  (`/logo/...`, `/css/...`, `/ui/...`, `/vusb/...`) keep `relURL`.

- Internal links inside translated Markdown use `relref`: `[x]({{< relref "docs/usb" >}})`
  resolves to `/zh/docs/usb/` on the zh site. Plain `/docs/usb/` links are not
  rewritten and point at the English page.

### i18n catalogs (`i18n/{en,zh,es}.toml`)

- One key per string, with `other = "..."`. Every language must carry the same
  keys as English.
- **Keys that map to data values must match the value exactly, hyphens included.**
  Status values are `stand-in` and `not-ported`, so the keys are
  `status_stand-in` and `status_not-ported` (not `status_standin`). Kind keys are
  like `kind_logic-analyzer`. These are looked up with
  `{{ T (printf "status_%s" $best) }}` — a hyphen mismatch silently renders empty.
- **Prose that contains a link** uses a `{link}` placeholder and `replace` +
  `safeHTML`, so punctuation stays natural per language:

  ```html
  {{ $how := printf "<a href=\"%s\">%s</a>" (relLangURL "testing/") (T "home_col3_link") }}
  <p>{{ replace (T "home_col3_p") "{link}" $how | safeHTML }}</p>
  ```

  with `home_col3_p = "... hardware. {link}."` in the catalog.
- Single-param substitution: `{{ T "home_stat_drivers" $m.libsigrok_total }}`
  uses `{{ . }}` in the string. Multi-param: pass a `dict` and use `{{ .name }}`.

### Injecting strings into JavaScript

`jsonify` inside a `<script>` gets double-escaped (`var x = "\"copy\""`). Always
append `safeJS`:

```js
var COPY = {{ T "copy" | jsonify | safeJS }};
```

Same for any string fed into JS that uses `{placeholder}` replacement.

### Pagefind (search)

- Pagefind reads the **`lang` attribute** on `<html>` — not `data-pagefind-lang`.
- It recognizes `zh`, `zh-cn`, `zh-tw` (not `zh-Hans`). The `lang` attribute must
  therefore be the language key, not the locale:

  ```html
  <html lang="{{ .Site.Language.Lang }}">
  ```

  (`hreflang` still uses `.Language.LanguageCode` = `zh-Hans` for SEO.)

### CI tag selection (deploy.yml)

`sort -V` misorders a pre-release after its release (`v0.2.0-alpha.1` >
`v0.2.0`), so the site would build against the alpha. The tag picker maps `-` to
`~` (which `sort -V` ranks before the release) and back:

```sh
tag=$(git ls-remote --tags ... 'v*' | ... \
  | sed 's/-/~/' | sort -V | tail -n1 | sed 's/~/-/')
```

## Version references (cli and ui)

Version strings live in two places and both must be updated on release:

- **Generated (no edit here):** the home-page banner and demo install command
  come from `data/drivers.json` (`meta.version`, `meta.demo`); the UI version is
  `data/ui.json` → shown via the `{{% uiversion %}}` shortcode.
- **Changelog:** the oxrok page follows the oxrok checkout; the oxrok-ui
  notes are added by hand to `assets/changelog/ui.md` (see "Changelog").
- **Hand-written (edit these):** `content/install.md` and `content/start.md`
  (and their `content/zh/` and `content/es/` copies) hard-code the install
  command and the terminal version banner. Grep for the old version string
  across `content/` and update every copy.

## Changelog (`/changelog/`)

Two pages, `/changelog/oxrok/` and `/changelog/ui/`, in every language. Each
is a stub in `content/{,zh/,es/}changelog/` (translated title and intro,
`type: changelog`, `source:`) and `layouts/changelog/single.html` renders the
Markdown file `source` names under `assets/`. So the release notes exist
once, in English, and are not translated; only the stubs are.

- **oxrok: generated, never edit.** `assets/changelog/oxrok.md` is
  `../oxrok/CHANGELOG.md` minus its preamble and an empty "Unreleased"
  section. A missing or wrong entry is fixed in the oxrok repo's
  `CHANGELOG.md`. CI builds against the newest oxrok tag, so the page shows
  that release's changelog with no change here.
- **oxrok-ui: hand-maintained, update on every UI release.** The UI repo has
  no changelog file, so `assets/changelog/ui.md` is committed. On each
  oxrok-ui release, in the same change that runs `make ui`:
  1. Take the release notes: `gh release view v<version> -R oxrok/oxrok-ui
     --json body --jq .body`, or the "Release notes" section of the release
     pull request when the GitHub release is not out yet.
  2. Add them **at the top** of `assets/changelog/ui.md` under
     `## [<version>] - <YYYY-MM-DD>` (the tag's date), with the notes' own
     headings at `###`. Copy the text as released: do not rewrite it, and
     leave out what is about the pull request (checks, checklists).
  3. Keep older releases below, unchanged.

  If oxrok-ui gains a `CHANGELOG.md`, import it in `tools/sync-ui.py`
  instead and drop these steps.
- The headings must stay `## [<version>]`: the list page reads the newest one,
  and `tools/check.py` fails the build when `assets/changelog/ui.md` does not
  start at the version in `data/ui.json`, or when the oxrok changelog has no
  section for the version the site is built against.
- Raw HTML in the notes is not rendered (Hugo's default), and a relative
  link would point into this site: use full URLs.

## Build and check

- `make` = `ui data pages docs hugo pagefind check` (see `Makefile`). Local
  builds need the `../oxrok` and `../ui` checkouts, plus `hugo` and `pagefind`.
- `tools/check.py` verifies: generated data is valid, every driver has a status,
  no broken internal links, no page over 100 KB, no "libsigrok bug" mentions,
  UI screenshots match their manifest, and the changelogs have the releases
  the site is built for.
- Verify a change locally with `hugo` then `pagefind -s public` then
  `python3 tools/check.py` before pushing.

## Known flakiness

The Hugo download step (`peaceiris/actions-hugo@v2`) intermittently 504s in CI.
It has built-in retries but still fails often; `gh run rerun <id> --failed`
usually gets it through. Hardening that step (cached/pinned Hugo binary) is an
open TODO.
