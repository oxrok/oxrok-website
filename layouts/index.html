How it was written

oxrok is a translation of the sigrok C and Python code into Rust, done by a large language model, with a human directing the work: choosing what to port, reviewing the structure and the protocol handling, wiring up the bench hardware and running the comparisons. Read the code with that in mind, and read the driver table for what has met which kind of evidence.

How it is tested

We don't own the hardware for most of these drivers, so we make the kernel think we do: each is a model in Rust, attached over USB/IP (vhci-hcd) so it's a real USB device as far as the kernel is concerned. The real sigrok-cli and oxrok then run unmodified against the same device, every transaction logged and compared. The models are built to misbehave — stalls, unplugs, late replies, bad frames. The whole method, and its limits.
